# Security model

LXReview deliberately runs its dedicated Claude worker with bypass permissions. It does not change permission mode in ordinary Claude conversations.

Workers have an explicit tool list, no subagent tools, no external MCP servers, and run-scoped `PreToolUse` hooks. Claude's Bash sandbox is explicitly enabled with `failIfUnavailable` and no unsandboxed fallback; missing sandbox prerequisites fail rather than weaken the policy. No worker turn has network access. Evaluation is read-only. The edit/test turn may run the project's own tooling, one literal command at a time: hooks refuse shell composition and expansion, shells and wrapper commands (`bash`, `env`, `xargs`, `sudo` and similar), `GIT_*`, loader and `PATH` assignments, Git mutations, commands that modify files outside the repository and the turn's private scratch directory, and paths to credentials. The sandbox confines writes to the repository (Git metadata, hooks and tool configuration such as `.claude`, `.gitmodules` and `.lfsconfig` excluded) and a private per-turn directory, and hides credentials and private data: the installation root, `~/.config` (except Git's own configuration), `~/.claude`, SSH, GnuPG, cloud, container and package-registry credentials, keyrings, browser profiles, shell histories, Kerberos ticket files and `.env` files. The one exception in `~/.claude` is the directory where Claude Code saves the current session's oversized command output, which Claude's Read, Grep and Glob tools may open. The publication turn may only stage and commit, with no Co-Authored-By or Claude attribution.

Before each evaluation, LXReview reads the PR's or MR's discussion outside the sandbox through one read-only GraphQL query: a GitHub PR's with your `gh` login, a GitLab MR's anonymously from the GitLab host (no GitLab credentials are used); Claude receives it as untrusted text, and each pass keeps a copy in its audit directory. LXReview itself verifies that publication added exactly one commit on top of the reviewed head and left no uncommitted changes, then signs (if configured) and pushes it outside the sandbox with the user's credentials, to the existing upstream by an explicit refspec. Push policy checks reject force/mirror refspecs and alternate destinations in Git configuration. Pre-push hooks are not run for these pushes, since they could execute files the worker changed; commit hooks run inside the sandbox. A repository setup command from `[verify.setup]` runs outside the sandbox before the worker edits anything; it comes from the user's own configuration and must not source repository files.

These protections are defense in depth, not a claim that hooks safely execute arbitrary hostile projects. Test code and commit hooks are executable code; use a disposable branch and trusted repository. A failing check or push is never fixed by disabling the sandbox. User or enterprise Claude managed settings may further restrict operation.

Playwright drives Chrome over a private pipe, so Chrome opens no debugging port. The browser service accepts calls only on a 0600 unix socket in a 0700 per-user runtime directory (`/run/user/<uid>`, or the private installation root where the host has none), with a per-start bearer token. VNC and the relay bind only to loopback. SSH reverse forwarding explicitly binds `127.0.0.1` on the exact LXPLUS node. Loopback is not a user boundary: relay bearer authentication remains mandatory. A fresh challenge checks server possession of the relay token before the client sends its bearer to a potentially stale port. Pairing uses a single-use ten-minute nonce. Relay credentials rotate on bridge creation, expire after at most eight hours, and are sent over SSH stdin, never argv. A disconnected bridge is unavailable, and credentials expire even when remote cleanup cannot run. The relay accepts only named package operations and no arbitrary URL or file proxying.

Private roots/directories use 0700 and secrets/state use 0600. Runtime archives are pinned by SHA-256 and Python dependencies by `uv.lock` hashes; Playwright never downloads browsers. Downloads are staged and checked before extraction. Browser state is never copied, exported or shared. No OpenAI API, cookie extraction, CAPTCHA bypass, or MFA bypass exists.

Events redact credential-shaped keys/values and drop thinking/signature blocks. Raw reviewer responses are preserved verbatim by contract, so do not send credentials to the reviewer. Audit artifacts may contain proprietary code and should be handled as private repository data. The package cannot reliably recognize every arbitrary secret embedded in source text; inspect reports before sharing them.

Installer integration refuses command collisions. Uninstall removes only registrations and links that still match ownership records. It archives the private root for recovery; delete the archive for complete removal. No shell startup, conda, global npm, user VNC startup or unrelated browser process is modified.
